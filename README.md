# 景区客流安全调度

面向安全值班席的客流调度服务。把闸机计数、接驳容量、设施运行状态、气象告警和
匿名位置区段汇成**带置信度**的分路段/分节点占用估计；数据迟到或传感器失联时
系统不假装精确——自动下调置信度、改用更保守的阈值，并把动作降级为需要人工确认。

## 领域模型

- **拓扑**（`data/topology.json`）：节点（入口/换乘点/站点/景点/出口）与有向路段
  （接驳、步道、徒步、索道、天梯）。路段带容量、通行时间、体力等级、单向标记、
  气象分区与关闭窗口（绝对区间或每日时段）。
- **事件**（`scenic/events.py`）：每个事件同时携带 `observed_at`（现场发生时间）与
  `received_at`（到达时间），乱序与迟到是一等公民；迟到事件按观测时间回填并记录。
- **占用估计**（`scenic/occupancy.py`）：闸机进出推算与匿名区段观测互为校验，取值
  取保守上界；置信度随观测老化、传感器失联/心跳超时、来源分歧、近期迟到而衰减。
- **调度决策**（`scenic/dispatch.py`）：每条限流/关闭/疏散决策都说明所用规则、
  受影响路径、触发依据与解除依据。置信度 ≥0.7 用常规阈值（90%）自动限流；
  0.4–0.7 改用保守阈值（75%）并需人工确认；<0.4 用最保守阈值（60%）。
- **临时管制**（`scenic/controls.py`）：必须记录发起人与到期时间，到期自动失效；
  解除需两名独立操作员确认，发起人不得参与解除。
- **路线与疏散**（`scenic/routing.py`）：推荐路线尊重单向路段、关闭窗口、体力等级，
  按占用动态加权，并生成多语种（中/英/日/韩）指引；已进入危险区段的游客按占用
  降序优先生成疏散路径，必要时允许逆行单向路段（明确标记 `contra_flow`）。

## 回放与重启

值班席用项目内拓扑与乱序事件流（`data/events.json`）回放峰值客流：迟到回填、
传感器失联、暴雨红色告警、索道停运与恢复、管制双人解除依次发生；回放末尾通过
快照-恢复模拟服务重启，并校验重启前后决策一致。

```bash
python3 service.py --check    # 基础检查（含回放与重启一致性）
python3 service.py --replay   # 打印完整回放报告（JSON）
python3 service.py --port 8000
```

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 健康检查 |
| GET | `/api/state` | 当前估计、决策、管制、设施状态 |
| GET | `/api/decisions` | 决策列表（规则/受影响路径/依据/解除依据） |
| GET | `/api/evacuation` | 当前疏散优先计划 |
| GET | `/api/routes?from=&to=&lang=&exertion=` | 多语种路线推荐 |
| POST | `/api/events` | 汇入事件（单个或数组） |
| POST | `/api/controls` | 发起临时管制（`expires_at` 必填） |
| POST | `/api/controls/release` | 操作员确认解除（需两人） |
| POST | `/api/replay` | 回放项目内事件流 |
| POST | `/api/restart` | 快照-恢复模拟服务重启 |
